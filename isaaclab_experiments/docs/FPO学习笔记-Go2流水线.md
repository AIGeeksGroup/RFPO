# FPO 学习笔记：Go2 从「状态」到「动作」，策略怎么更新

面向初学者。尽量少用英文缩写；出现时都会先用中文解释。  
对应任务：平地上让宇树 Go2 机器狗跟上速度指令（仓库里的 Go2 速度跟踪任务）。

---

## 1. 先回答你的两个直觉问题

### 1.1 网络是不是「输入机器人姿态，输出动作」？

**基本是，但更准确一点说：**

- **输入**：机器人当前状态（不只有姿态，还包括速度、关节角、速度指令等）
- **输出**：下一步要发给腿的动作（这里是 12 个关节的目标角度）

可以把它想成一个「驾驶大脑」：

```text
看到现在狗是什么状态、要往哪走
        ↓
      神经网络
        ↓
决定每条腿的关节往哪摆
```

在这个仓库里，这个「大脑」不是一步直接吐出动作，而是：

1. 先从一团随机噪声开始  
2. 神经网络告诉你「噪声该往哪个方向流」  
3. 一步步流完，最后变成动作  

这种生成动作的方式叫 **流匹配**（flow matching）。  
外面整套「采集数据 → 算好坏 → 改网络」的强化学习方法，在本仓库里叫 **FPO**（用流模型当策略的策略梯度方法）。

你暂时可以记成：

> **策略 = 这套神经网络（加上下面的积分步骤）**  
> **更新策略 = 改这些网络权重（参数）**

### 1.2 「策略更新」和「网络参数更新」是什么关系？

**在这个实现里，它们几乎是同一件事。**

| 口语说法 | 实际在代码里做什么 |
|----------|-------------------|
| 策略（policy） | 就是那套「流网络 + 积分出动作」的规则 |
| 策略更新 | 根据这一轮交互数据，算出「该朝哪个方向改」 |
| 网络参数更新 | 用优化器（如 Adam）真正去改网络里的数字（权重） |

关系可以写成一句话：

```text
策略更新（算法想清楚怎么改）
        ↓
算出损失（一个衡量「当前网络好不好」的数）
        ↓
反向传播 + 优化器
        ↓
网络参数真的变了  ← 这就是一次参数更新
        ↓
策略变了（因为策略就是由这些参数定义的）
```

所以：

- 不是「先更新策略、再更新网络」两件无关的事  
- 而是：**策略用网络参数来表示；更新策略 = 更新这些参数**

下面按时间顺序，把「一整轮训练」拆开。

## 2. 这个任务里，输入输出具体是什么

### 2.1 输入（状态）大概有什么

Go2 策略网络看到的状态大约 48 个数，包括：

- 机身线速度、角速度  
- 身体有没有歪（重力方向投影）  
- **速度指令**（告诉它「你该往哪走、转多快」）  
- 12 个关节的角度、角速度  
- 上一步输出的动作（帮助动作更平滑）

所以不只是「姿态照片」，而是一整包本体感觉 + 任务指令。

### 2.2 输出（动作）是什么

- 12 个数：每个活动关节一个 **目标角度**  
- 仿真里还有底层 PD 控制器：负责把关节真正拧到这些目标附近  

你训练的神经网络负责「想目标」；底层控制器负责「用力去够」。

### 2.3 怎样算做得好：奖励

每走一步，环境会打分，例如：

- 速度跟指令越近 → 加分  
- 乱蹦、歪倒、抖动太猛、力矩太大 → 扣分  

强化学习的目标：改网络参数，让长期累计得分变高。

## 3. 网络内部长什么样（Go2 默认）

有两块网络，分工不同：

### 3.1 行动网络（Actor，演员）

职责：**根据状态，生成动作**。

在 FPO 里，它学的是「流的速度」：

- 输入 = 状态 + 时间信息 + 当前中间向量  
- 输出 = 「中间向量接下来该怎么变」  
- 从噪声积分很多次（默认约 64 小步）→ 得到最终动作  

Go2 默认结构大致是：多层全连接，宽度 256。

### 3.2 评价网络（Critic，评论家）

职责：**估计「当前状态大概能拿多少回报」**，记作价值 \(V\)。

- 不直接控制腿  
- 用来判断「这一步动作是比平均更好，还是更差」  
- 这个「更好/更差」叫 **优势**（advantage）

Go2 默认结构更宽一点（多层宽度 768）。

记住：

```text
行动网络 → 出动作（控制狗）
评价网络 → 打分辅助学习（不直接控制狗）
两者的参数都会在训练里被更新
```

---

## 4. 从噪声到动作：行动网络怎么用（推理 / 交互时）

每一步控制循环：

```text
第 1 步：拿到当前状态 s
第 2 步：准备一个初始向量 x
         - 训练采集时：常常用随机噪声
         - 网页回放「zero」模式：常常用全 0（更稳定）
第 3 步：重复很多次（例如 64 次）：
         问行动网络：在当前状态、当前时间、当前 x 下，该往哪流？
         得到一个方向 u
         更新：x ← x + u × 一小步时间
第 4 步：积分结束后的 x，就是动作 a（12 维关节目标）
第 5 步：把 a 交给仿真环境，得到奖励 r 和新状态
```

你可以把它想成：

> 网络不是「直接说答案」，而是「一次次指路」，把噪声一步步领成合法动作。

---

## 5. 一整轮训练流水（最重要）

训练是一轮一轮做的。你设的 1500，就是大约做 1500 轮这种循环。  
每一轮大致分四段：**采集 → 算优势 → 更新参数 → 存盘/记日志**。

---

### 阶段 A：采集数据（狗在仿真里跑一阵）

同时开很多只仿真狗（例如 2048 只），每只走固定步数（例如每轮每只 24 步）。

对每一步做：

1. 用**当前**行动网络，按上面第 4 节，从状态算出动作 \(a\)  
2. 环境执行，得到奖励 \(r\)、下一步状态、是否结束  
3. 额外算并保存一个数：叫 **旧的流匹配损失**（下面第 6 节解释）  
4. 用评价网络估一个价值 \(V\)，后面算优势要用  

这些 \((状态, 动作, 奖励, 旧损失, \ldots)\) 先全部存进缓冲区，**这一阶段通常先不改网络**。

类比：

> 先按现在的驾驶习惯开一圈，把仪表数据记下来，下课再复盘改习惯。

---

### 阶段 B：算「这一步动作好不好」（优势）

用评价网络和奖励，估算：

- 回报目标：从这步往后大概能拿多少分  
- **优势**：这一步动作，比「这个状态下的平均水平」好多少  

直觉：

| 优势 | 含义 | 更新时期望 |
|------|------|------------|
| 大于 0 | 这步动作比平均好 | 让网络以后更常做出类似动作 |
| 小于 0 | 这步动作比平均差 | 让网络以后少做类似动作 |
| 接近 0 | 一般般 | 改动不大 |

这一阶段主要是在算数，**仍然还没改网络权重**。

---

### 阶段 C：根据数据，真正更新网络参数（策略更新发生在这里）

拿出阶段 A 存的数据，切成小批量，反复多遍（多个 epoch）。

对每个小批量：

#### C1. 用「当前」行动网络，重算一遍流匹配损失

对当时那个动作 \(a\)，再问一遍：  
「以你现在的参数，这个动作和流模型匹配得怎么样？」  
得到 **新的流匹配损失**。

#### C2. 用新旧损失差，代替「概率比」

普通策略梯度常用「新旧策略概率比」。  
FPO 没有简单的高斯概率，于是用：

```text
比值 ≈ exp( 旧流匹配损失 − 新流匹配损失 )
```

直觉（不必死记公式）：

- 若新损失更小：网络现在更「认」这个动作 → 比值变大  
- 若新损失更大：网络现在更不认这个动作 → 比值变小  

#### C3. 结合优势，组成「策略损失」（代理目标）

大致精神：

- 优势为正：希望比值变大（更支持好动作）  
- 优势为负：希望比值变小（少支持坏动作）  
- 同时用裁剪 / 惩罚，防止一次改太猛（本仓库 Go2 默认一种偏稳的 trust-region 写法）

另外还有 **价值损失**：让评价网络的 \(V\) 更准。

总损失大致是：

```text
总损失 = 策略相关损失 + 系数 × 价值损失
```

#### C4. 反向传播 + 优化器 → 参数更新

```text
总损失
  → 自动求导：每个权重「往哪拧能让损失按目标变好」
  → Adam 等优化器真正改行动网络、评价网络的参数
  → 可选：维护行动网络的滑动平均副本（更平滑的一版参数，常用于评估）
```

**到这里，「策略更新」才落到「网络参数真的变了」。**

改完参数后：

- 同一套结构  
- 但权重不同  
- 再遇到相似状态，积出来的动作就会不同  
- 也就是策略变了  

---

### 阶段 D：记日志、存模型

- 打印平均奖励、各项奖励分解等  
- 隔一段时间保存 `model_xxx.pt`（里面主要是网络参数等）  

你以后用网页看狗，就是加载这些参数，再走第 4 节的「状态 → 积分 → 动作」。

## 6. 「流匹配损失」是干什么的（帮助理解更新）

训练行动网络时，除了和环境交互，还要让网络学会「正确的流向」。

很粗的说法：

1. 已知一个动作 \(a\)（采集时已经做出来的）  
2. 再随机采一个噪声，和一个时间比例 \(t\)  
3. 在「噪声」和「动作」之间取一个中间点  
4. 网络预测：这个中间点应该往哪流  
5. 和「理想流向」比，差多少就是 **流匹配损失**（越小说明越会流到这个动作）

FPO 巧妙之处：

- 采集时记下「旧参数」下的损失  
- 更新时算「新参数」下的损失  
- 用两者差来构造比值，再乘优势去做类似 PPO 的更新  

你可以先记这句：

> 流匹配损失 ≈「网络有多擅长把噪声变成这个动作」的误差；  
> FPO 用它的变化，来代替普通策略里的概率比。

## 7. 把「策略更新」和「参数更新」再钉死一遍

下面这条链，建议多读两遍：

```text
① 当前网络参数 θ  定义了  当前策略 πθ
         │
         │  （阶段 A）用 πθ 在仿真里走路，收集数据
         ▼
② 根据奖励和评价网络，算出每步优势
         │
         │  （阶段 B）
         ▼
③ 用数据构造总损失 L（和优势、新旧流匹配损失有关）
         │
         │  （阶段 C）
         ▼
④ 对 L 求导，优化器更新：θ → θ'
         │
         ▼
⑤ 新参数 θ' 定义了新策略 πθ'
         │
         ▼
⑥ 下一轮再用 πθ' 去采集 …… 循环几千轮
```

所以：

- **策略更新**：指算法从 ① 走到 ⑤ 的整套逻辑  
- **网络参数更新**：特指第 ④ 步「θ 变成 θ'」  
- 没有单独另一个「不经过网络」的策略物体；**策略就是参数化的网络行为**

---

## 8. 和「真机部署」的关系（超短）

训练时有完整的 A→B→C。  
真机或网页回放时，通常只做：

```text
读传感器 → 拼成和仿真一致的状态
    → 用已保存的网络参数积分出动作
    → 发给机器人
```

没有「算优势、算流匹配比值、Adam 更新」——那些只在训练服务器上发生。

## 9. 用生活类比收尾

| 概念 | 类比 |
|------|------|
| 行动网络 | 学开车的人的「肌肉习惯」 |
| 评价网络 | 副驾教练：估计「这样开以后能得多少分」 |
| 采集阶段 | 按现有习惯上路，记下每一次操作 |
| 优势 | 复盘：这一脚油门是好是坏 |
| 流匹配 + 比值 | 一种衡量「习惯有没有更偏向好操作」的尺子 |
| 参数更新 | 晚上根据复盘改习惯（改脑子里的连接强度） |
| 存 checkpoint | 把这一版习惯存成存档 |
| 网页可视化 | 读档，看狗现在开得怎样 |

## 10. 建议你怎么学这份笔记

1. 先只看第 1 节和第 7 节（关系搞清）  
2. 再看第 4 节（状态怎么变成动作）  
3. 再看第 5 节 A→C（一轮训练）  
4. 最后需要时再啃第 6 节（流匹配损失）  

训练还在跑时，你在日志里看到的：

- `Mean reward`：狗整体表现  
- `surrogate_loss`：和策略更新相关的损失  
- `value_loss`：评价网络估得准不准  

对应的就是上面阶段 C 里那两类损失。
